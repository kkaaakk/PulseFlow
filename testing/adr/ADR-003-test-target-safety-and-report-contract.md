# ADR-003：强制测试目标隔离并明确报告状态

> 中文说明：本决策确定所有测试必须使用 loopback/测试数据库，并用 `PASS`、`FAIL`、
> `NOT_RUN` 区分真实结果。环境缺失、安全检查失败、依赖不存在或断言失败都必须返回
> 非零，防止产生虚假的全绿结果。

## 状态

已接受

## 背景

Replay 会写入事件，Validator 可能查询或准备 Campaign 数据，因此必须拒绝误指向生产
URL 或生产数据库的操作。Windows 环境可能没有 Docker 或 k6，但基础设施不可用不能
被误报为 PASS。

## 决策

默认只允许本机回环 HTTP/Redis/MySQL 目标；存储校验必须同时满足
`PULSEFLOW_TEST_ENV=test` 和测试数据库名；使用隔离的 Compose 端口及测试数据库；
每份报告都必须输出 `PASS`、`FAIL` 或 `NOT_RUN`。任何失败、不安全目标、缺少命令行
工具或断言失败都返回非零。

## 影响

### 正面影响

- 测试工具不会轻易把有写入能力的准备步骤指向明显的生产目标；
- CI 和本地报告可以区分基础设施不可用与真实成功；
- 失败证据同时适合机器读取和人工阅读。

### 负面影响

- 开发者必须显式配置测试环境变量；
- 非回环测试环境必须显式授权，不是默认路径。

## 备选方案

- **完全信任调用者传入的 URL**：对 Replay 工具不安全，因此不采用；
- **将缺少 Docker/k6 视为 PASS**：会制造虚假的绿色验收结果，因此不采用。
